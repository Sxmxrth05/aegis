# Project Overview

## About the Project

**Aegis** is an autonomous multi-agent system for orbital collision de-confliction. Today, when two satellites from different operators risk colliding, resolution happens through manual emails between engineers — there is no standardized, automated negotiation protocol. Aegis replaces that manual process with autonomous negotiation agents, one per satellite operator, that detect a shared conjunction event from real tracking data and negotiate who maneuvers.

Each agent reasons over its own satellite's constraints — mission priority, fuel margin, maneuver cost, and (in later phases) debris-cascade risk, propulsion type, space weather, and ground-station availability — and proposes/counter-proposes a resolution over multiple rounds. A deterministic cost function (never free-form LLM text) decides who actually yields; the LLM's job is narration and structured tool-calling only. A third agent validates the winning maneuver doesn't create a new downstream collision before it's finalized.

The product is a live dashboard: a 3D globe showing tracked satellites and debris, a conjunction alert flow, a real-time negotiation console showing agents "talking," and a resolution view with the agreed maneuver and its rationale.

---

## The Problem It Solves

Orbital traffic coordination today has no real-time, automated negotiation layer. As LEO gets more crowded (Starlink, OneWeb, and thousands of smaller satellites), manual, email-based collision avoidance doesn't scale and introduces dangerous delay. Aegis demonstrates what an automated, auditable, multi-agent coordination protocol could look like — grounded in real orbital tracking data, not a hypothetical.

## Core User Flow

1. **Landing** — visitor sees the mission statement and headline stats (active satellites tracked, debris tracked, safety improvement %). CTA buttons: "Watch Demo" (plays a recorded run) and "Explore Live Map" (routes to `/monitor`).
2. **Monitor** — the 3D globe renders the curated tracked-object set in real time (from cached/live TLE data). A conjunction alert appears as a highlighted pair with a warning marker. Selecting the alert surfaces a summary panel and a "View Negotiation" button.
3. **Negotiate → Conjunction Details** — shows both satellites' key stats (operator, altitude, velocity, fuel delta-v, mission priority, maneuverability) side by side, plus the conjunction's time-of-closest-approach, minimum distance, and collision probability. A "Start Agent Negotiation" button triggers the negotiation flow.
4. **Negotiate → Negotiation Console** — two-column live transcript, one column per operator agent, messages streaming in as the backend negotiation progresses through rounds (visible round tracker: Initial Proposals → Negotiation → Agreement → Verification → Final Plan). Each message pairs natural-language justification with the underlying numbers driving it.
5. **Negotiate → Result** — shows the agreed plan (who maneuvers, maneuver type, execution time, expected post-maneuver miss distance and residual risk) and a human-readable rationale. A mini before/after trajectory preview links out to the full Trajectory Simulation.
6. **Trajectory Simulation** — the globe in a before/after toggle mode with a timeline scrubber, showing the original and new trajectories and how risk changes over time.
7. **History** — a filterable table of past conjunctions and their resolutions, for auditability.
8. **About** — mission framing, data sources (CelesTrak, NOAA), and a clearly labeled roadmap of Phase 2 features not yet built.

## Data Architecture

- **TrackedObject** — a satellite or debris item from the curated demo set. Sourced live/cached from CelesTrak TLE data; not owned by any user (shared/public data).
- **ConjunctionAlert** — a detected close-approach event between two TrackedObjects. Generated by the Conjunction Monitor Agent (deterministic, no LLM). Public/shared data, not per-user.
- **NegotiationSession** — the multi-round negotiation tied to one ConjunctionAlert. Contains an ordered list of NegotiationMessages from each Operator Agent.
- **NegotiationMessage** — one agent's turn: its computed yield_score (deterministic) plus LLM-generated justification text. Immutable once emitted.
- **Resolution** — the final agreed maneuver plan for a NegotiationSession, plus the Validation Agent's approval status and rationale.
- **CreditLedgerEntry** *(Phase 2)* — simulated service-credit transfer between operators when one yields for the other.

This is a demo/simulation product with no user accounts in the MVP — all data is shared/public rather than per-user owned. If auth is added later, TrackedObjects and ConjunctionAlerts remain global/shared; only saved views or annotations would be user-scoped.

## Features In Scope

- Real TLE ingestion (CelesTrak) + SGP4 propagation
- Deterministic conjunction detection on a curated demo object set, with at least one guaranteed scripted close-approach scenario
- Two Operator Agents negotiating on Mission Value Index (MVI) + fuel/Δv cost (MVP scope)
- Deterministic yield_score cost function, called as a tool by the LLM (LLM never invents the number)
- Validation Agent performing a short-horizon (6h, extending to 48h in Phase 2) re-check of the proposed maneuver against the tracked set
- "No safe maneuver found" as a valid, honestly-presented outcome
- Live 3D globe (react-globe.gl) showing tracked objects, alerts, and before/after trajectories
- Real-time negotiation console showing agent dialogue tied to underlying numbers
- History log of past conjunctions and resolutions

---

## Features Out of Scope

- Real per-satellite mass/thruster/mission data (all Phase 2 factors — DCP, propulsion arbitration, space weather adaptation, TTNP, geopolitical hierarchy, orbit credits — use simulated/approximated inputs, clearly labeled as such)
- Full-catalog (~30k object) real-time conjunction scanning — demo uses a curated subset
- User accounts, auth, or per-user saved data
- Actual satellite command/telemetry integration — this is a decision-support/demo system, not a live operational tool
- Payment processing for the Orbit Credits ledger (simulated numbers only)
- Judge chaos-injection controls (stretch goal, not MVP)

---

## Target User

Primary: hackathon judges evaluating technical depth, multi-agent reasoning, and real-world relevance. Secondary (for framing/credibility): satellite operators, space-traffic-management researchers, and space policy stakeholders who would recognize the real coordination gap this addresses.

---

## Success Criteria

- A real TLE-sourced conjunction is detected and displayed on the live globe without manual intervention
- Two agents visibly exchange at least 2 rounds of proposals/counter-proposals with numeric justification before converging
- The final yield_score and Δv shown in the UI trace back to a deterministic backend calculation, never an LLM-generated number
- The Validation Agent rejects at least one proposed maneuver during the demo and forces a re-negotiation
- The globe updates to reflect the agreed maneuver's new trajectory
- The system runs end-to-end off cached data with no live-network dependency required for the demo
- A judge can ask "how do you know the AI isn't just making this up" and get a concrete, verifiable answer from the UI itself
